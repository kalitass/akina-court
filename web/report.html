2What is built

Three agents, four dispute types, every exchange on the record; four additional safeguards on top.

Core

  • Three agents. Two advocate agents pull evidence through logged tools, write a brief and an append-only rebuttal; a tool-less judge answers only the questions the policy engine left open. Each is a separate role contract. Court feed (replay page)
  • Structured ruling and plain-language notices. Structured ruling with outcome, amount, model confidence, reasoning, cited facts and clauses, rejected claims, and a plain-language notice to each party. Ruling card · Reproducibility receipt
  • Evidence from every source. Every synthetic case file carries a 5-second GPS trace (the organisers' samples have one point every 2–4 minutes), the quoted route, chat, driver statement, fare breakdown, LTA traffic bands and incidents, weather and both profiles; code turns them into a numbered fact table. Fact table
  • Four dispute types. Route deviation, no-show / cancellation fee and surge pricing, plus safety, which always goes to a person — 7 hand-built demo cases and 50 benchmark cases. Demo cases · Benchmark
  • Every exchange on the record. Every tool call, brief, rebuttal point, judge question and verifier check is an event streamed live (server-sent events) and replayed in the court feed with timestamps. Replay page (Run live needs a local copy with a DeepSeek key)

Additional safeguards

  • Precedent store. Rulings are indexed; a new case retrieves similar past cases by fact values and the judge sees them as context (never as evidence). A ruling that contradicts strong precedents raises a warning.
  • Bad-faith signals. Code-computed signals — arrival tap far from the pickup, waiting claim unsupported by GPS, jam claim unsupported by traffic data, repeat offender — enter the fact table as citable facts. C-0004 with the screen on
  • SLA routing and review queue. Each ruling is routed: auto-resolve, 24-hour review, or urgent safety (2 h). Anything the certificate cannot clear, any account action and any high signal goes to a human.
  • Human feedback loop. A reviewer's override is recorded, becomes a human-labelled precedent that outranks automatic ones, and feeds an override-rate statistic per dispute type.

3Key features

The AI argues; only verified policy executes.

  1. The policy runs before the model. Ryde's dispute rules are compiled into executable predicates: on every case, code first decides which of the policy's clauses apply, which fail and which need a reading, and the model speaks only inside that remaining space. A ruling rests on the written policy, not on the model's memory of it, which removes the room for an invented rule at the source.
  2. Every ruling is verified by code, and a change to what it rests on shows on its receipt. The facts are computed by code from the GPS trace, the chat, the fare, traffic and weather records: numbered, identical on every run; the advocates and the judge may cite only those numbers and the clause ids. Before anything executes, code checks the ruling item by item: every cited id exists, the outcome is one the policy allows, the amount equals the policy formula to the cent, a consent message precedes the detour it excuses. Each ruling carries a receipt with four fingerprints (case file, policy, code, model), so a change to the case, the policy, the code or the model shows on the receipt. Stored hearings of the demo case C-0001 put 4 deliberate faults into the AI's output (an invented clause, a cited fact that does not exist, an account flag hidden in free text and a changed amount) and a prompt injection into the chat: each was caught, and none led to an action the untampered hearing would not take.
  3. The reasoning is fully transparent and the standard is documented. Every tool call, brief, rebuttal, ruling, check and notice is a timestamped event, streamed live and replayable step by step on the map; every citation opens the fact or the clause it points to. Across the benchmark the court made 883 citations, 0 of them invalid.
  4. Adversarial agents beat the same model alone. Same model, same 50 cases. The raw case file handed straight to the model: 21 of 50 right or handed to a person, 29 wrong decisions executed. The judge with the code check but no advocates: 44 of 50, 6 wrong decisions executed. The full court (code facts, two advocates, judge, code check): 50 of 50, 0 wrong decisions executed. The advocates add what a single judge lacks: each side states the policy ground of every open question, and a ruling against a reading both sides share goes back to the judge once for a second look.
  5. Fraud is screened by code before anyone argues. A bad-faith screen runs over the record before the advocates speak: an arrival tap far from the pickup, a waiting claim the GPS does not show, a jam claim the traffic record does not support, a repeat offender on file. Each signal enters the fact table as a numbered fact with the evidence it rests on, so the advocates and the judge can cite it and the audience can check it. On the no-show case C-0004 the screen found 3 signals and the judge cited 3 of them; the ruling and the amount are the ones the bare court reached, and the account action still goes to a person. The benchmark itself runs without the screen, so its figures are the bare court's.

Responsible AI

  • Safety complaints and account actions are never automated; a threat in the chat stops the court and the case goes to a person.
  • Insufficient evidence is a formal finding: a GPS hole, a missing record or an agreement the record cannot tie to the road sends the case to a person, with what is missing named.
  • The notices to rider and driver are plain language, and their amounts are checked by code against the final ruling.

Caveats

  • The reference answers follow the written policy, not the decisions of a human support team.

How the reference answers were made, and what the numbers can and cannot say

  • Each benchmark scenario is written around one trap (a wait or a notice close to a time limit, a rider's agreement in Singlish or Chinese, a false arrival tap, a driver's own reason recorded as a no-show, frustrated words that are not a threat, a gap in the GPS trace). The reference answer is produced by running the policy engine on the scenario's own labels — what the rider meant, whether a message is a threat — and checking it against the trap the scenario was written for.
  • The court's pre-execution check and the reference answers share that policy engine. A shared bug would therefore be invisible to this benchmark: the result is a policy-conformance test, not evidence that the written policy or its implementation is what a human ops team would decide.
  • Raw LLM receives the case JSON with the GPS trace thinned to one point every 30 s (native sampling 5 s) to fit the context window; everything else is verbatim. It is never given fact ids, so it cannot cite them.
  • All four systems use the same model with the same temperature settings.
