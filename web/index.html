Akina Court is a multi-agent court for ride-hailing disputes: route deviation, no-show fees, safety. Today a support agent settles each one by hand.

A ride dispute settled in 26 seconds, every ruling on the record.

The rider gets an AI advocate; the driver gets one too. Each argues its side, but only from facts that code computed first: the GPS track against the best route, every message, every fare line. An AI judge rules on what the policy leaves open. Before anything happens, code checks every citation, the allowed outcome and the amount against a public, numbered policy. A refund that passes is cleared as a voucher; safety cases, account actions and any failed check go to a person with the file ready.

Every ruling is traceable

Transparent reasoning is not a log the model writes about itself. It is a chain the code enforces: numbered facts, a public policy, citations that must resolve, and checks on the record.

1 · EVIDENCE

Facts from every source, computed by code

Platform records (booking, taps, fare lines, GPS every 5 s in the synthetic cases, 90-day histories), both parties' own words, and external records: the best OneMap route, LTA speed bands and incidents, weather. Each becomes a numbered fact, identical on every run. Words are copied, never interpreted by code: what they meant is for the court. Missing evidence is a fact of its own.

See the fact table →
2 · POLICY

A public, numbered, sourced policy

21 clauses, each with its source: Ryde's own terms, Singapore regulations, or comparable platforms' published rules. The 11 clauses the three dispute types need run as code and fix the allowed outcomes before any model speaks; the rest are citable text.

Read the policy →
3 · AGENTS

Agents that can only cite

The rider's and driver's advocates read facts through logged tools and write claims that cite fact ids and clause ids, then rebut each other point by point. A claim citing something unknown or unread is struck in public. The judge rules only on the questions the policy leaves open, reads what the messages meant, and may say the record cannot settle it.

Watch the court →
4 · CHECKS

Every check on the record

Citation check, allowed-outcome check, amount to the cent, account flag only as a structured field. One self-correction round, then a human. Each ruling carries a receipt with case, policy, code and model fingerprints that is re-verified on request.

How to read it

  • What the model is given matters most: 27 → 33 when the same model receives code-computed facts instead of the raw record.
  • The code check blocks wrong executions: 31 and 31 wrong decisions acted without it; with it, 7 and 0 of 65.
  • The advocates close the gap the judge alone leaves: judge + check leaves 7 wrong decisions executed (58/65 right or handed to a person); the full court leaves 0 (65/65): both sides' reasoning on the record, a policy ground each side states for every open segment, and a judge bound to the grounds argued.

"Match" means agreement with the policy-derived reference: a policy-conformance measure, not production accuracy. Model, run window, token counts, audit sample and how to recompute every number: method and data · per-case tables and confusion matrices: full results.

  • Riders, drivers, trips and reference outcomes are generated; no live Ryde data; wallet and trust-and-safety connectors are not included

Human control

  • The model cannot create facts, amounts, punishments or safety decisions; it proposes interpretations and wording
