Akina Court is a multi-agent court for ride-hailing disputes: route deviation, no-show fees, surge pricing, safety. Today a support agent settles each one by hand.

A ride dispute settled in 30 seconds, every ruling on the record.

The rider gets an AI advocate; the driver gets one too. Each argues its side, but only from facts that code computed first: the GPS track against the best route, every message, every fare line. An AI judge rules on what the policy leaves open. Before anything happens, code checks every citation, the allowed outcome and the amount against a public, numbered policy. A refund that passes is approved to go back to the rider's original payment method; safety cases, account actions and any failed check go to a person with the file ready.

Every ruling is traceable

Transparent reasoning is not a log the model writes about itself. It is a chain the code enforces: numbered facts, a public policy, citations that must resolve, and checks on the record.

1 · EVIDENCE

Facts from every source, computed by code

Platform records (booking, taps, fare lines, GPS every 5 s in the synthetic cases, 90-day histories), both parties' own words, and external records: the best OneMap route, LTA speed bands and incidents, weather. Each becomes a numbered fact, identical on every run. Words are copied, never interpreted by code: what they meant is for the court. Missing evidence is a fact of its own.

See the fact table →
2 · POLICY

A public, numbered, sourced policy

31 clauses built on the official Ryde Dispute Resolution Policy, each with its source; where the official policy is silent, Ryde's published help pages and a few system rules, marked as such. The policy runs as code and fixes the allowed outcomes before any model speaks.

Read the policy →
3 · AGENTS

Agents that can only cite

The rider's and driver's advocates read facts through logged tools and write claims that cite fact ids and clause ids, then rebut each other point by point. A claim citing something unknown or unread is struck in public. The judge rules only on the questions the policy leaves open, reads what the messages meant, and may say the record cannot settle it.

Watch the court →
4 · CHECKS

Every check on the record

Citation check, allowed-outcome check, amount to the cent, account flag only as a structured field. Each failed check goes back to the judge once; if it still fails, a person decides. Each ruling carries a receipt with case, policy, code and model fingerprints that is re-verified on request.

How to read it

  • Clean facts alone barely help: 21 → 24 when the same model receives code-computed facts instead of the raw record; the mistakes are in applying the policy.
  • The code check blocks wrong executions: 29 and 26 wrong decisions acted without it; with it, the judge and the full court let 6 and 0 of 50 through.
  • The advocates close the gap the judge alone leaves: judge + check leaves 6 wrong decisions executed (44/50 right or handed to a person); the full court leaves 0 (50/50): both sides' reasoning on the record, a policy ground each side states for every open segment, and a second look whenever the judge departs from a reading both sides share.

"Match" means agreement with the policy-derived reference: a policy-conformance measure, not production accuracy. Model, run window, token counts and how to recompute every number: method and data · per-case tables and confusion matrices: full results.

How it works

Three layers; only the middle one is a language model, and it never acts on its own.

What is real, what is synthetic, what the model never decides

Working

  • API, UI and event stream; deterministic fact and policy code; sourced policy; OneMap road geometry; audit receipts

Synthetic benchmark

  • Riders, drivers, trips and reference outcomes are generated; no live Ryde data; payment and trust-and-safety connectors are not included

Human control

  • The model cannot create facts, amounts, punishments or safety decisions; it proposes interpretations and wording
